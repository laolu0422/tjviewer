# 日志问题根因分析与修复验证（1.0.6）

## 1. 问题现象

1.0.6 发布后，按预期到 `%ProgramData%\TjViewer\logs` 查找运行日志时，只能看到：

- `service-yyyyMMdd.log`（后台服务）
- `secure-agent-yyyyMMdd.log`（安全桌面代理，仅在触发 UAC/锁屏时出现）
- `secure-launch.log`（服务拉起代理的诊断）
- `install.log`（安装器）

**没有客户端日志，也没有服务端日志**，导致无法复现和定位客户端/服务端问题。

## 2. 排查范围与证据

### 2.1 代码检索

对 1.0.6 代码（提交 `77ed20a`）检索所有日志写入点：

| 位置 | 日志实现 | 落盘 |
| --- | --- | --- |
| `TjViewer.Service/SessionLauncher.cs` | `File.AppendAllText(... service-yyyyMMdd.log)` | 是 |
| `TjViewer.SecureAgent/Program.cs` | `File.AppendAllText(... secure-agent-yyyyMMdd.log)` | 是 |
| `TjViewer.Service/SecureAgentLauncher.cs` | `File.AppendAllText(... secure-launch.log)` | 是 |
| `TjViewer.Server/Program.cs` 及各 Endpoint | 仅 `ILogger`（默认 Console Provider） | **否**（只输出到控制台） |
| `TjViewer.Client/App.xaml.cs` 及全部客户端代码 | **无任何文件日志** | **否** |

关键命令与结果：

```text
git grep -n "AppendAllText|StreamWriter|ILogger" HEAD -- src/TjViewer.Client src/TjViewer.Server
→ 客户端仅匹配到 SecureDesktopBridge 的管道 StreamWriter；
→ 服务端只有 ILogger 注入，无文件写入。

git log --all --oneline -S "AppendAllText" -- src/TjViewer.Client src/TjViewer.Server
→ 无任何提交记录（历史版本也从未实现过客户端/服务端文件日志）。
```

### 2.2 目录与权限

`scripts/install-client.ps1` 会创建 `%ProgramData%\TjViewer\logs` 并授予 `BUILTIN\Users` 修改权限：

```text
IdentityReference      FileSystemRights  AccessControlType
BUILTIN\Users          Modify            Allow
NT AUTHORITY\SYSTEM    FullControl       Allow
```

实测非提权进程可在该目录创建并追加文件，**不是权限问题**。

### 2.3 版本对比

`git log --all -S "FileLog"`、`-S "AppendAllText"` 在客户端/服务端路径下均无记录；
1.0.6 发布包与 1.0.5 之前的代码一致，均没有客户端/服务端文件日志能力。
因此**不是 1.0.6 引入的回归，而是该能力一直缺失**：1.0.6 只是在安装说明中强化了“日志目录”预期，
用户按说明去找客户端/服务端日志时自然一无所获。

## 3. 根因结论

1. **直接原因**：客户端与服务端都没有实现文件日志；服务端 `ILogger` 默认只写控制台，
   作为 Windows 服务或双击启动后窗口关闭，日志即丢失。
2. **放大因素**：`%ProgramData%\TjViewer\logs` 仅在安装器创建时对 Users 授权；
   便携运行/权限受限环境下没有降级目录，即使后续补日志也可能因目录不可写而再次“看不到日志”。
3. **排查误导**：同一目录下存在 `service-*`、`secure-agent-*` 日志，容易被误认为“客户端日志写不进去”。

## 4. 修复方案

### 4.1 新增共享文件日志引擎

`src/TjViewer.Shared/Logging/FileLog.cs`（无第三方依赖）：

- **目录优先级**：
  1. `TJVIEWER_LOG_DIR`（环境变量覆盖，便于临时排查/容器部署）
  2. `%ProgramData%\TjViewer\logs`
  3. `%LOCALAPPDATA%\TjViewer\logs`
  4. 应用目录 `logs`
  5. `%TEMP%\TjViewer\logs`
  6. 非 Windows：`/var/lib/tjviewer/logs` → 应用目录 → 临时目录
- **命名/切割/格式**：`{app}-yyyyMMdd.log`，按自然日切换，UTF-8 追加；
  行格式 `yyyy-MM-dd HH:mm:ss.fff [LEVEL] [app] 消息`；异常附完整堆栈。
  **不修改** `service-*`、`secure-agent-*`、`secure-launch.log` 的既有命名与格式。
- **级别**：DEBUG / INFO / WARN / ERROR，默认全部写入。
- **可靠性**：
  - 启动时对每个候选目录做“创建目录 + 追加探针”验证，不可写自动降级；
  - 运行中写入失败：关闭句柄、切换到下一个可用目录并继续写入；
  - 在可用目录写 `logging-alert.log`（含失败原因与切换结果），同时输出到 `Trace`；
  - 任何日志异常均被吞掉，绝不影响业务；
  - 每次写入立即 `Flush`，异常退出不丢最后一段日志。
- **自检**：`TJVIEWER_LOG_SELFTEST=1` 启动时写入四个级别 + 异常样例，用于发布后验证。

### 4.2 服务端接入

`src/TjViewer.Server/Program.cs`：

```csharp
builder.Logging.ClearProviders();
builder.Logging.SetMinimumLevel(LogLevel.Debug);
builder.Logging.AddSimpleConsole(...);
builder.Logging.AddDebug();
builder.Logging.AddProvider(new FileLoggerProvider("server"));
builder.Logging.AddFilter("Microsoft.EntityFrameworkCore", LogLevel.Warning);
builder.Logging.AddFilter("Microsoft.AspNetCore", LogLevel.Information);
```

- `src/TjViewer.Server/Logging/FileLoggerProvider.cs` 将 `ILogger` 映射到 `FileLog`；
- 启动/停止、监听地址、版本、内容根写入 `server-yyyyMMdd.log`；
- 新增全局异常中间件：未处理请求异常写入 ERROR + 堆栈后继续抛出；
- 框架调试日志限制到 EF Warning / ASP.NET Information，避免日志被 SQL 细节淹没。

### 4.3 客户端接入

`src/TjViewer.Client/App.xaml.cs`：

- 启动第一行 `FileLog.Initialize("client")`，早于单实例互斥与 UI 初始化；
- 注册三个全局异常钩子：`DispatcherUnhandledException`、`AppDomain.UnhandledException`、
  `TaskScheduler.UnobservedTaskException`（记录 ERROR + 堆栈，不改变原有崩溃行为）；
- 记录启动参数/版本/日志目录、登录窗口、登录成功、退出登录；
- `FFmpegLocator.Diagnostics` 输出记录为 DEBUG；
- 关键交互补充日志：关闭行为选择/记忆、托盘设置、完全关闭、开机自启开关、会话建立/中转/拆除、
  安全桌面接管/回切。
- 不记录密码、令牌、验证码等敏感信息。

```text
[INFO] 日志初始化：应用=server 目录=C:\ProgramData\TjViewer\logs（已降级，首选目录=Q:\no-such-dir\logs）...
logging-alert.log:
```

即：首选目录不可用时自动降级、继续写日志，并留下可发现的告警记录。

## 6. 现场排查指引

1. 先看 `%ProgramData%\TjViewer\logs` 当日文件：
   - 客户端问题：`client-yyyyMMdd.log`
   - 服务端问题：`server-yyyyMMdd.log`
   - 会话拉起/守护：`service-yyyyMMdd.log`
   - UAC/锁屏：`secure-agent-yyyyMMdd.log` + `secure-launch.log`
   - 日志系统自身降级：`logging-alert.log`
2. 需要复现启动阶段问题时，设置 `TJVIEWER_LOG_SELFTEST=1` 启动一次，确认四个级别与异常堆栈写入正常。
3. 需要把日志写到其他位置时，设置 `TJVIEWER_LOG_DIR`（优先级最高）。
4. 若日志目录无写入权限，客户端会依次尝试 LocalAppData、应用目录、临时目录；请以日志首行
   “日志初始化：… 目录=…” 为准，不再出现“找不到日志”的情况。

> 说明：本次未改动 `service-*`、`secure-agent-*`、`secure-launch.log` 的命名、切割与格式，
> 仅新增客户端/服务端文件日志与统一兜底机制。
