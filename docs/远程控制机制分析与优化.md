# 远程控制机制分析与优化（对标 uu 远程）

> 说明：uu 远程（网易 UU 远程）为闭源商业软件，没有公开源码或授权材料，**本文不包含、也不使用其任何私有代码**。
> 下文关于 uu 的部分是基于其公开资料、客户端行为观察与远程桌面领域的通用实现所做的**架构级推断**，
> 用于确定优化方向；TjViewer 的改造均为独立实现。文中明确区分「推断」与「本项目已实现」。

## 1. 远程控制的核心链路

任何低延迟远程控制软件都可拆成五段，端到端延迟是五段之和：

```
采集 → 预处理/编码 → 传输 → 解码/渲染 → （输入回传）
```

| 环节 | 关键指标 | 常见瓶颈 |
| --- | --- | --- |
| 采集 | 单帧耗时、是否阻塞 | 同步读回、每次分配大缓冲、编码反压采集 |
| 编码 | 编码时延、队列深度 | 软件编码、编码器初始化、无界队列积压 |
| 传输 | RTT、丢包重传、拥塞 | TCP 队头阻塞、窗口过小、码率超带宽 |
| 解码 | 解码时延、队列深度 | 帧缓冲策略、硬件加速未启用 |
| 输入 | 注入时延、特殊桌面 | UIPI/UAC 安全桌面、坐标换算 |

## 2. uu 远程的机制推断（架构级）

### 2.1 画面采集

- **Windows 10+ 优先 Windows.Graphics.Capture（WGC）**，旧系统回退 DXGI Desktop Duplication：WGC 能更好地处理窗口遮挡、受保护内容和多显示器，DXGI 则延迟更低、可直接拿到 GPU 纹理。二者通常按系统版本与场景动态选择。
- **光标分离**：采集画面不带鼠标指针，指针位置作为独立元数据发送，控制端本地合成。这样鼠标移动不需要重编码整帧，是「鼠标跟手」的关键。
- **按需采集/脏区域**：画面静止时降低采集与编码频率，只发送心跳或关键帧；有变化时立即恢复。避免持续编码静止画面浪费 GPU 与带宽。
- **特殊画面**：UAC/锁屏运行在 Winlogon 安全桌面，普通进程无法采集；成熟产品通常通过 **uiAccess 签名进程 + 系统服务** 或驱动进入安全桌面抓屏。
- **GPU 零拷贝**（推断）：采集纹理直接交给硬件编码器（NV12/NVENC/QSV），避免 `CPU 读回 → 内存拷贝 → 再上传` 的三次搬运。

### 2.2 预处理与编码

- **BGRA → NV12 在 GPU 上完成**（像素着色器/视频处理器），硬件编码器直接消费 NV12。
- **硬件编码优先**：NVENC / QSV / AMF，软件 x264 仅兜底；低延迟参数：无 B 帧、`low_delay`、关闭 look-ahead、单帧异步深度。
- **自适应码率/帧率**：持续测量发送积压、RTT、丢包与解码反馈，动态调整分辨率/帧率/码率；网络突变时快速降档，稳定后缓慢升档。
- **关键帧控制**：检测到丢包/花屏/切换编码器时请求 IDR；部分产品使用帧内刷新（intra refresh）替代大关键帧，减少码率尖峰。

### 2.3 传输

- **UDP 承载 + 私有可靠传输**（KCP/QUIC 类）：视频帧允许丢弃过期数据，控制信令可靠重传，避免 TCP 队头阻塞。
- **P2P 打洞优先，失败自动中转**；中转节点按地域/运营商就近选择。
- **FEC 前向纠错 + 选择性重传**：轻微丢包不重传，靠冗余恢复；关键帧丢失才重传。
- **带宽探测与拥塞控制**：类似 GCC/BBR 的发送速率控制，避免把链路打爆导致延迟飙升。
- **多路复用**：视频、音频、输入、文件共用一条加密连接，按优先级调度（输入 > 视频 > 文件）。

### 2.4 解码与渲染

- **D3D11VA/D3D12 硬件解码**，解码输出直接作为纹理渲染（零拷贝），避免 CPU 帧缓冲。
- **只保留最新帧**：渲染线程忙时丢弃旧帧，保证「延迟优先于帧率完整性」。
- **抖动缓冲自适应**：网络抖动大时略增缓冲，稳定时压到最小。
- **光标本地合成 + VSync 策略**：光标不经过视频链路；根据显示器刷新率选择呈现方式，减少撕裂与额外一帧延迟。

### 2.5 输入控制

- **扫描码注入**（`SendInput` + `KEYEVENTF_SCANCODE`），规避键盘布局差异；文本用 Unicode 注入。
- **相对鼠标模式**：FPS/游戏场景使用相对位移，避免绝对坐标跳变。
- **键盘钩子**：控制窗口激活时捕获 Alt+Tab、Win 等系统快捷键并透传。
- **UAC/安全桌面**：必须以 uiAccess 或系统服务身份在 Winlogon 桌面注入；普通进程会被 UIPI 拦截。
- **Ctrl+Alt+Del（SAS）**：属于安全注意序列，用户态程序无法模拟，只能提示用户或使用键盘驱动/硬件方案。

### 2.6 稳定性与体验

- 首帧加速（预热编码器/解码器）、断线自动重连、会话保持、音画同步、统计信息面板（延迟/丢包/帧率/码率）。
- 客户端与后台服务分离：服务负责开机自启、进程守护与安全桌面代理拉起，客户端负责交互与媒体。

## 3. 本项目（TjViewer）现状与本次改进映射

| 模块 | uu（推断） | TjViewer 改造前 | 本次改进 |
| --- | --- | --- | --- |
| 采集 | WGC/DXGI 动态选择、光标分离、脏区域 | DXGI（失败回退 GDI），同步采集；无更新时重复上一帧 | DXGI 仅在有新帧时返回；帧直接写入复用帧池；安全桌面强制 GDI 并绑定输入桌面 |
| 编码 | GPU 零拷贝 + 硬件编码 | 采集线程内同步 `WriteAsync + Flush`，慢编码器反压采集 | 采集/编码解耦：帧池 3 帧 + 有界队列 2 帧，溢出丢新帧；编码线程按参数重建编码器 |
| 传输 | UDP + FEC + 拥塞控制 | KCP/UDP + 服务器中转回退，`NoDelay(1,5,2,1)` | 保持；发送积压持续 1 秒才降档，避免抖动 |
| 解码 | 硬解 + 最新帧优先 | D3D11VA + `nobuffer/low_delay`，渲染端丢旧帧 | 保持 |
| 输入 | 扫描码/相对鼠标/安全桌面 | SendInput 扫描码；UAC 下无能力 | SecureAgent 在 winlogon 桌面采集并注入；修复检测与拉起时序 |
| 日志 | 本地可诊断 | 服务/代理有日志，客户端/服务端无文件日志 | 新增 client/server 按天文件日志 + 异常堆栈 + 降级告警 |

## 4. 已实施的关键优化

### 4.1 采集/编码解耦（修复 iGPU 被控端卡顿）

改造前（`HostVideoSender.CaptureLoop`）：

```text
采集一帧 → 同步 EncodeFrameAsync(frame).Wait() → 下一帧
```

编码器（尤其 Intel QSV 初始化、高负载软编）一慢，采集线程就被阻塞：
实际帧率下降、编码队列在管道内堆积，端到端延迟持续增大，表现为画面卡顿、操作滞后。

改造后：

1. **帧池**：3 个固定尺寸 BGRA 缓冲循环复用，采集直接写入（`CaptureFrameInto`），不再每次分配 8MB 数组。
2. **有界队列**：容量 2；队列满或帧池耗尽时**丢弃新帧**，绝不阻塞采集。
3. **独立编码线程**：按帧携带的宽/高/帧率/码率消费队列；参数变化时在编码线程重建编码器并发送新的 `VideoInfo`。
4. **恢复采集强制 IDR**：安全桌面结束、本地恢复时重建编码器，避免解码端沿用代理码流的参考帧导致花屏。
5. **静止画面不重复编码**：DXGI 无更新时不再复制/编码上一帧；控制端保持最后一帧，输入引起的画面变化在一个帧周期内送达。

### 4.2 UAC / 锁屏（安全桌面）修复

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| UAC 界面无法检测 | 普通权限进程 `OpenInputDesktop` 在安全桌面返回 `NULL`，旧逻辑把失败当作“非安全桌面” | 打开失败即判定为安全桌面；连续 2 次采样去抖（300ms 间隔） |
| 代理偶发连接超时 | 先请求服务拉起代理、后创建管道服务端，存在竞态 | **先创建管道服务端，再请求拉起代理** |
| 代理 500ms 后自行退出、UAC 黑屏 | 代理周期性判断输入桌面，桌面切换瞬间误判 | 代理生命周期只跟随管道；安全桌面结束由客户端关闭管道触发退出 |
| UAC 画面黑屏 | DXGI 在 winlogon 桌面不可用/黑屏 | 代理**强制 GDI 采集**，并把采集线程绑定到输入桌面（`OpenInputDesktop + SetThreadDesktop`） |
| UAC 操作无响应 | 代理未在安全桌面注入，或管道时序错误 | 代理在 winlogon 桌面以 SYSTEM + uiAccess 运行，输入/画质消息经管道转发注入 |

### 4.3 端到端延迟预算（1080p，局域网）

| 环节 | 优化后预算 | 说明 |
| --- | --- | --- |
| 采集 | 1–4 ms | DXGI 等待 2–4ms，有新帧立即返回 |
| 编码排队 | ≤ 2 帧 | 队列满立即丢弃，不累积 |
| 硬件编码 | 5–15 ms | NVENC/QSV 低延迟参数，无 B 帧 |
| 传输 | 5–20 ms | KCP 5ms 快节拍 + P2P 直连 |
| 解码 | 3–10 ms | D3D11VA + `nobuffer` |
| 渲染 | ≤ 1 帧 | 只保留最新帧 |

## 5. 与 uu 仍存在的差距（后续路线）

以下能力属于进一步逼近商业产品的方向，本次未全部实现，需按优先级排期：

1. **WGC 采集 + GPU 零拷贝**：目前编码前需 CPU 读回 BGRA 再交给 ffmpeg；下一步可改为 D3D11 纹理 → NV12 着色器 → 硬件编码器，省掉两次内存搬运。
2. **FEC / 拥塞控制**：当前依赖 KCP 重传与自适应档位；弱网下可加入前向纠错与带宽探测。
3. **光标元数据通道**：当前 DXGI 画面不含光标、控制端本地渲染；可补充远端光标形状（I 型、缩放等）同步。
4. **多显示器与高 DPI**：目前以主显示器为采集目标；多屏需增加显示器选择与坐标映射。
5. **Ctrl+Alt+Del**：用户态无法模拟 SAS，需要驱动或硬件方案，暂不支持。
6. **统计面板**：可在控制窗口展示实时延迟/丢包/帧率/码率，便于现场定位。

> 由于 uu 远程闭源，无法对其内部实现做逐行对标；本项目以“同等能力目标”推进：
> 低延迟采集编码、P2P/中转、硬件编解码、安全桌面可采集可操控、日志可追溯。

## 6. 验证方法

- **日志**：`%ProgramData%\TjViewer\logs\client-yyyyMMdd.log`、`server-yyyyMMdd.log`；
  设置 `TJVIEWER_LOG_SELFTEST=1` 可在启动时写入 DEBUG/INFO/WARN/ERROR 与异常样例。
- **UAC**：被控端触发 UAC 后，日志应出现“检测到安全桌面”“已请求拉起 SecureAgent”“安全桌面接管已建立”；
  控制端应看到 UAC 画面并可点击“是/否”；UAC 结束后日志出现“安全桌面已结束，回切本地采集”。
- **卡顿**：被控端播放 1080p 视频或拖动窗口，观察控制端帧率是否稳定、操作是否跟手；
  日志中不应出现连续的“编码写入失败”，发送积压不应持续增长。
- **降级**：把 `TJVIEWER_LOG_DIR` 指向不存在的盘符，启动后应生成
  `%ProgramData%\TjViewer\logs\logging-alert.log`，并继续在可用目录写日志。
